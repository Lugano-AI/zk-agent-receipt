# Fairness-review guest fixes: before/after execute-only cycles

Updated: `2026-11-09`

## What changed between the two measurements

Both rows of every table below use the same deterministic fixture
(`DEFAULT_FIXTURE_SEED`), the same `risc0-accelerated` guest feature, and the
same RISC Zero 3.0.6 toolchain. The only differences are the two fairness
fixes applied to the guest:

- **Fix 1**: the P128Pow5T3 round constants and MDS matrix are embedded as
  canonical-limb `const` tables (`relation/src/poseidon_constants.rs`,
  generated by `relation/src/bin/generate_poseidon_constants.rs`) instead of
  being derived inside the guest by `<P128Pow5T3 as Spec>::constants()` on
  every run. A native test asserts the embedded tables equal `Spec::constants()`.
- **Fix 2**: the Schnorr verifier's two scalar multiplications (`generator * s`,
  `public_key * challenge`) and the final `R + c * PK` addition run over the
  `risc0-bigint2` affine short-Weierstrass precompiles configured for Pallas
  (`relation/src/pallas_accelerated.rs`) instead of portable `pasta_curves`
  arithmetic. All validity checks are retained: on-curve, non-identity,
  `s < q`, and canonical encodings are still checked via the portable parser
  before the accelerated path runs, and the bigint2 point ops assert canonical
  coordinates against a dishonest host.

No relation check was dropped or weakened. The before source tree is
snapshotted in `before-source/`; the before measurements in `before/` were
taken with it.

## Execute-only cycles (no proving), 3 deterministic attempts each

Cycle counts are RISC Zero's actual session counters and were identical
across all attempts at each T in both runs. The AFTER run was executed under
a concurrently loaded machine (load average ~14.7 of 18 cores); cycle counts
are load-independent, but the AFTER wall-clock medians in `after/results.md`
must not be quoted as quiet-machine timings.

| T | total cycles before | total cycles after | Δ total | user cycles before | user cycles after | segments before | segments after |

| 10 | 33,685,504 | 20,971,520 | −12,713,984 (−37.7%) | 31,643,346 | 19,739,301 | 33 | 20 |

## Linear fit `cycles ≈ slope × T + intercept`

Least squares over T = 10, 100, 1000:

| metric | slope before | intercept before | slope after | intercept after |
| --- | ---: | ---: | ---: | ---: |
| total cycles | 735,223 | 23,971,612 | 737,546 | 11,446,955 |
| user cycles | 695,970 | 22,530,142 | 701,756 | 10,545,826 |

Interpretation: the fixed, T-independent term dropped by ~12.5M cycles
(−52% of the intercept), which is the fix 1 constant-derivation plus fix 2 Schnorr
scalar-multiplication overhead leaving the per-run fixed cost. The per-entry
slope is essentially unchanged (within 0.8%), as expected: the fairness fixes
did not touch per-entry transcript hashing or Merkle work.

## Verification evidence (AFTER build)

All commands run with `PATH="$HOME/.risc0/bin:$PATH"`; host binary at
`target/aarch64-apple-darwin/release/baseline-host`.

- `cargo +risc0 test --target aarch64-apple-darwin -p relation --lib --test requirements`
  — 24 passed, 0 failed (12 lib incl. embedded-constants and Pallas-curve
  tests, 12 adversarial requirements). Includes the fix 1 host test
  `embedded_poseidon_constants_match_spec`.
- `RISC0_DEV_MODE=0 cargo +risc0 test --target aarch64-apple-darwin -p baseline-host`
  — 1 passed (`receipt_modes_select_real_composite_and_succinct_options`).
- `baseline-host check-arithmetic` (RISC0_DEV_MODE=0) — guest bigint2 field,
  Poseidon, and Pallas-curve self-tests match the native portable oracle
  (`accelerated_guest_self_test_matches_native: true`). JSON in
  `after/validation/check-arithmetic.json`.
- `baseline-host negative --t 10 --case …` (dev mode, with same-process
  positive control proving with the accelerated-Schnorr guest) — all four
  cases `rejected-as-expected`: wrong-tool → `InvalidToolPath`,
  wrong-transcript → `TranscriptMismatch`, wrong-signature →
  `InvalidSignature` (exercising the new bigint2 Schnorr path), wrong-nullifier
  → `NullifierMismatch`. JSON in `after/validation/`.

No proving benchmark was run during this review; the serial proving commands
are documented in `README.md`.
